# ddd4j-boot 3.4.x 适配 ddd4j 2.0.x 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `ddd4j-boot feature/3.4.x` 全面适配 `ddd4j feature/2.0.x` 核心契约，使所有 starter 使用 Boot 3 `@AutoConfiguration` 注册机制，SPI 生命周期、Repository、ThreadContext 在应用关闭/测试上下文重建后无残留，并为每个自动配置补齐 `ApplicationContextRunner` 契约测试。

**Architecture:** `ddd4j-boot` 定位为依赖选择器、Spring Boot 条件装配层、SPI 生命周期协调器、配置属性层和契约测试载体。不复制 `ddd4j-core` 的领域模型、CQRS 算法、Repository、消息消费模板或 Web 统一语义；优先消费 `ddd4j-runtime-spring`、`ddd4j-web-*`、`ddd4j-data-*`、`ddd4j-mq-*`、`ddd4j-auth-*`。

**Tech Stack:** Java 17、Spring Boot 3.4.13、Spring Framework 6.2.19、Maven、JUnit 5、ApplicationContextRunner、Testcontainers。

## Global Constraints

- 版本基线：`ddd4j-boot` revision `3.4.x.20260630-SNAPSHOT`，`ddd4j` revision `2.0.x.20260630-SNAPSHOT`。
- 严禁使用 Git worktree。
- 所有模块使用 Boot 3 `@AutoConfiguration` + `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册。
- 用户 Bean 始终通过 `@ConditionalOnMissingBean` 优先于默认实现。
- SPI、Repository 和 ThreadContext 在应用关闭/测试上下文重建后无残留。
- 外部基础设施测试（MQ broker、数据库等）通过显式 profile 开启，`mvn verify` 默认跳过。
- 每个自动配置必须有 `ApplicationContextRunner` 契约测试。
- 不在 Boot 中复制上游已实现的能力。

## 1. 架构结论与实施边界

### 1.1 核心定位

- `ddd4j` 已形成"纯契约/核心模型 -> 能力 SPI -> 技术适配器 -> runtime 容器桥"的结构。
- `ddd4j-boot` 承担：依赖选择器、Spring Boot 条件装配层、SPI 生命周期协调器、配置属性层和契约测试载体。
- 不在 Boot 中复制 `ddd4j-core` 的领域模型、CQRS 算法、Repository、消息消费模板或 Web 统一语义。

### 1.2 已确认基线

| 组件 | 版本 |
|------|------|
| ddd4j-boot | `3.4.x.20260630-SNAPSHOT` |
| ddd4j | `2.0.x.20260630-SNAPSHOT` |
| Spring Boot | `3.4.13` |
| Spring Framework | `6.2.19` |
| Java | 17（强制基线，21 兼容） |
