## 功能级结论

### 已吸收且已继续演进

以下重构方向已经成为当前 2.7 结构，不需要从历史提交迁移源码：

| 历史意图 | 当前归属 | 结论 |
|---|---|---|
| Security/Sa-Token/Shiro/License 从 cmpt 分离 | `ddd4j-boot-auth/*` | 已吸收，当前实现和测试更新 |
| Crypto/External/Logs/MyBatis 从 cmpt 分离 | `ddd4j-boot-data/*` | 已吸收，当前包名和上游边界更新 |
| Kafka 从 cmpt 分离 | `ddd4j-boot-mq/ddd4j-boot-mq-kafka` | 已吸收，当前使用统一 MQ Core 契约 |
| Akka/Excel/Jackson/PF4J/QLExpress | `ddd4j-boot-extensions/*` | 已吸收，当前模块和自动配置入口更新 |
| WebMVC/WebFlux 从 cmpt 分离 | `ddd4j-boot-web/*` | 已吸收，当前与 ddd4j Web Runtime 对齐 |
| Monitor 独立能力 | `ddd4j-boot-extension-monitor` | 已吸收并有自动配置测试 |
| MQ 聚合能力 | `ddd4j-boot-mq-core` + provider 模块 | 已吸收，不再采用单一 `ddd4j-boot-mq` 实现类集合 |

当前 `2.7.x` 已不存在旧 `ddd4j-boot-cmpt` 路径，说明“拆出 cmpt”这一结构目标已经完成。

### 已迁移到上游 ddd4j

历史 `ddd4j-boot-web-validation` 中的 `AllowedValues`、`NumberValue`、`PhoneNumber`、
`StringDateValue` 及其校验器已经由 `ddd4j feature/1.0.x` 的
`ddd4j-web-validation` 承担。Boot 不应重新复制这些普通 Web 校验组件。

### 不应迁移

1. `ddd4j-boot-ddd` 中的 `DddAggregateRoot`、`DddAggregateCommand`、`DddDomainEvent`、
   `DddEventStoreRepository` 只是 29–49 行的简化包装，且只在自身示例/Javadoc 中使用。领域模型、
   CQRS 和 EventStore 契约属于上游 ddd4j；当前 Boot Core 只承担自动配置桥接。重新引入会破坏边界。
2. `KafkaSendResultHandler` 只有 4 行空类，没有可观察行为，属于占位代码。
3. Cola/Dubbo 的 `Teszt` 是 4 行占位类，不迁移。
4. `BaseDataConfig`/`BaseDataProperties` 只相互引用，没有业务消费者，也没有测试，不应为目录对齐恢复。
5. 历史安全、加密、外部服务和 Web 类不能按旧包名迁移；当前模块已经依赖上游契约并采用新的 Boot
   自动配置入口。

### 需要另立需求评估，而不是从提交迁移

以下历史概念在当前 2.7 没有同名公共类型，但不能据此直接恢复：

- `MQEventPublisher`：当前 MQ Core 已采用 ddd4j 上游 MQ 契约；如确有统一发布门面需求，应从当前
  `MQClient`/事件序列化接口重新设计。
- `Ddd4jMonitorBootProperties`：当前 Monitor 自动配置已经存在并有上下文测试；只有出现真实配置需求
  时才增加属性，不恢复空属性类。
- `BaseDataProperties`：只有明确的数据层通用配置项和消费者时才建立，不创建无字段配置对象。

这些都不是本次分支收敛的迁移项。
