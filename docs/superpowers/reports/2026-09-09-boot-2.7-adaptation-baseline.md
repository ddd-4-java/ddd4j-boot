# ddd4j-boot 2.7.x 适配基线验证

日期：2026-09-09。

## 结论

`2.7.x` 已完成 ddd4j 1.0.x / TrueLicense 4 消费适配、Spring 5.3 样例兼容和 JDK 8 源码语法收敛。核心、Web、Auth、MQ、扩展及分层样例均通过；完整 72 模块 reactor 在 `ddd4j-boot-sample-starter-druid` 解析三个外部 Easy4J Starter 时停止，不能据此宣称整仓通过。

## 上游前置条件

- ddd4j `feature/1.0.x` 必须先提供 `SLF4J 1.7.36 / Logback 1.2.12` 的 `ddd4j-parent` 与 `ddd4j-dependencies`。
- 本轮先执行上游 `clean install`，确认本地正式 POM 包含上述版本，再使用 `-nsu` 验证 Boot，避免旧 SNAPSHOT 或陈旧 flatten 产物污染结果。

## 已验证行为

- `DefaultLicenseAutoConfigurationTest`：3 项通过，包括 `license.signature-algorithm` 向六参数 `LicenseVerify` 透传。
- 依赖边界测试：4 项通过；Boot 不再直接声明旧 `de.schlichtherle.truelicense` 构件。
- 13 条维护线矩阵、分支基线、契约数据和自动配置注册格式检查全部通过。
- Boot 2.7 Javalin 自动配置：7 项通过，证明上游日志版本恢复后不再缺失 `StaticLoggerBinder`。
- `ddd4j-boot-sample-domain` 使用 JDK 8 编译成功；record 值对象已替换为不可变 fluent 类，switch expression 已替换为传统 switch。
- 被外部依赖阻塞的 starter-druid 同构值对象使用 JDK 8 `javac` 独立编译成功。

## 完整 reactor 阻塞

`./mvnw -nsu -B -ntp clean package` 到达第 56/72 模块后，以下制品无法从配置的 Aliyun 仓库解析：

- `io.github.easy4j:redistpl-plus-spring-boot-starter:2.3.x.20240824.RELEASE`
- `io.github.easy4j:flyway-plus-spring-boot-starter:2.7.x.20260630-SNAPSHOT`
- `io.github.easy4j:druid-plus-spring-boot-starter:2.7.x.20260820-SNAPSHOT`

样例源码和配置实际使用 Redis/Flyway/Druid 能力，不能通过删除依赖刷绿。发布这些外部制品或提供可解析仓库后，应从根重新执行完整构建。
