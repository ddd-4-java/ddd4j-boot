【0】自查环境口径
--------------------------------------------------------------------------------
0.1 javadoc CLI 命令（仓库根目录执行，相对路径引用源文件）：
      "D:/Java/jdk-21.0.4/bin/javadoc" -Xdoclint:all \
        -Xmaxwarns 1000000 -Xmaxerrs 1000000 -quiet @<argfile> > <log> 2>&1
    - argfile（@file）书写规则：不接受 -J 标志；-encoding UTF-8 / -d <dir> /
      源文件列表逐行书写；argfile 内不支持通配符。
    - 源文件必须以仓根为 cwd 的相对路径列出，否则包结构解析失败。
0.2 日志解析口径：javadoc 日志为 GBK 编码，按
      raw = open(log,'rb').read().decode('gbk', errors='replace')
    解析，以 "警告" / "错误" 计数；-quiet 模式下无任何诊断 → 0 字节日志
    = 清零（配合 EXIT=0 与 HTML 生成时间戳三重验证）。
0.3 argfile -d 陷阱（过程事实，非失败）：原 args.txt 中 "-d" 与值分两行书写，
    派生批次 argfile 时前缀过滤无法去掉下一行的值 → javadoc 以 Windows 盘根
    解析，实际输出到 E:/tmp/jdoc-fw/out（而非脚本另附的 -d 目录）。
    验证不受影响：以 EXIT=0 + 0 字节日志 + E:/tmp/jdoc-fw/out/** 站点 HTML
    生成时间戳为本轮时刻 三重判定（见【3】）。
0.4 判定口径：跨工程依赖类（classpath）解析失败错误按任务纪律忽略；
    doclint 的 missing（缺注释/缺标签）、语法、标题层级、引用错误必须清零。
0.5 注释格式实测（探针 probe2，见【8】）：
    - 单行内联标签不被识别：`/** 获取值。 @return 值 */` 仍报「没有 @return」；
    - 必须使用多行紧凑格式：
        /** 描述。
         * @return 值 */
    - 类级文档隐式 H1 后正文标题必须从 <h2> 起（<h3> 报「标题超出序列」错误）；
    - {@link} 引用必须可解析：未 import 的外部类型用全限定 FQN 链接；
    - 公共类若无显式构造器，必然报「使用不提供注释的默认构造器」。
