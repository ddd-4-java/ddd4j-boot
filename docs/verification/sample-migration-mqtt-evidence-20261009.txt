[8] 编译疑点（交编排者 mvn 验证）
----------------------------------------------------------------
C1 pom mainClass 指向的类在 client1/client2/rocketmq 模块内不存在
   （真实启动类见 [3.1]）。若 spring-boot-maven-plugin repackage 对显式
   mainClass 做存在性校验，则该 3 模块 mvn package 可能失败——
   但 HEAD（迁移前 com.github.[[oldfam]]... 包前缀）同样不存在 → 非本次迁移回归。
   server 模块迁移后 mainClass 可解析（迁移反而修复）。
   如需彻底修复：将 3 模块 mainClass 改为各自真实启动类（DemoApplication /
   MqttClientApplication / DemoApplication）——待编排者裁定，本智能体未擅改，
   以保持与并行 hikaricp 先例的机械一致性。
C2 FlywayDemoConfiguration.java（client1/server/rocketmq）整文件为注释代码，
   无 package/编译单元 → 不参与编译，无影响。
C3 按任务约束未运行 mvn/gradle，最终以编排者 reactor 编译结果为准。
