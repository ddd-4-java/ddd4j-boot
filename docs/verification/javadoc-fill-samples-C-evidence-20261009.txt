【0】自查环境与判定口径
--------------------------------------------------------------------------------
0.1 javadoc CLI 命令（仓库根目录 ddd4j-boot 执行，源文件用仓根相对路径）：
      "D:/Java/jdk-21.0.4/bin/javadoc" -encoding UTF-8 -charset UTF-8 -d <out>
        -quiet -Xdoclint:all -Xmaxwarns 1000000 -Xmaxerrs 1000000
        -classpath <379+2 jar 并集> @<argfile> > <log> 2>&1; echo EXIT=$?
    - argfile（@file）：选项与源文件逐行书写，不支持通配符、不接受 -J 标志。
    - classpath 取自既有 maven javadoc 报告 target/reports/apidocs/options 的并集
      （379 jar）再补 spring-kafka-4.0.7.jar、kafka-clients-4.3.1.jar；
      补齐前基线报「程序包…不存在」717 条，补齐后归零，属环境准备而非代码问题。
0.2 日志解析口径：javadoc 日志为 GBK 编码，按
      raw = open(log,'rb').read().decode('gbk', errors='replace')
    以「警告」「错误」计数；-quiet 模式下无任何诊断 → 0 字节日志 = 清零
    （配合 EXIT=0 判定）。
0.3 【关键】同一 FQN 跨模块冲突会互相掩盖告警：5 个样本模块同包同名类
    （如 io.ddd4j.boot.sample.exception.BizExceptionCode 同时存在于 3 个模块），
    合并跑 javadoc 时 doclint 只对每个 FQN 的首个出现位置完整解析，
    导致合并基线只报 202 警告 + 9 错误，而逐模块基线合计 509 警告 + 9 错误。
    因此：【逐模块自查为权威判定】，合并跑仅作交叉复核。
0.4 注释格式实测口径（与非样本批次 C 口径一致）：
    - 单行内联注释块不被识别：`/** 描述。 @return 值 */` 仍报「没有 @return」；
    - 必须写成多行紧凑块：
        /** 描述。
         * @return 值 */
    - 类级文档隐式 H1 后正文标题从 <h2> 起；
    - 未 import 的外部类型在引用处写全限定名；
    - 公共类无显式构造器必然报「使用不提供注释的默认构造器」→ 补显式无参构造器
      （空方法体，与编译器默认构造器语义等价）；Lombok @Data 类补显式构造器后
      不再生成默认构造器，二者等价、无冲突。
    - 被整块注释掉的类（无任何声明）不产生告警，按纪律跳过不改：
      kafka / mqtt-client1 的 setup/config/FlywayDemoConfiguration.java 共 2 个。
0.5 classpath 错误按任务纪律忽略；doclint missing（缺注释/缺标签）、语法、
    标题层级、引用错误必须清零。
